백로그를 자동으로 소진하는 오케스트레이터다. 작업 범위: **$ARGUMENTS**

전제: 이 스킬은 `docs/backlog.md`(계획 인박스)와 `docs/bugs.md`(결함 인박스)가 있는 프로젝트에서 동작한다. **범위가 비어 있으면 백로그를 읽어 스스로 범위를 정해 진행한다**(아래 0-1의 자체 결정).

핵심 원리: **항목 하나 = 의미론적 브랜치 하나 = `--no-ff` 머지 하나.** 단, 모든 작업은 BASE가 아니라 **통합 브랜치** 위에 누적되고, 전체 계획이 끝났을 때 한 번만 BASE로 머지된다. 진행 상태는 계획 파일에 기록해 중간에 끊겨도 재개한다.

각 항목의 RED/GREEN/REFACTOR와 단계별 커밋은 `/tdd`에 위임한다. 이 스킬은 **계획 수립 · 계획 파일 관리 · 통합 브랜치 분기/머지 · 백로그 정리 · 루프 제어 · 재개**만 담당한다.

용어:
- `BASE`: 스킬 호출 시점의 브랜치(`master`, `dev` 등). 최종 산출물의 머지 목적지.
- `INTEG`: 이번 루프의 통합 브랜치(`loop/<슬러그>`). 모든 항목 브랜치가 여기로 머지되고, 계획 파일·백로그 변경도 여기서만 커밋한다.
- 계획 파일: `docs/tdd-loop-plan.md`. 이번 루프 동안만 존재하며 마지막에 삭제 커밋된다.
- **검증**: 프로젝트가 정의한 검증 명령(CLAUDE.md 참조), 없으면 전체 테스트 스위트. 아래 "검증"은 이를 가리킨다.

---

## 0. 시작 또는 재개 판정 (한 번만)

`docs/tdd-loop-plan.md`가 이미 있는지 확인한다.
- **있으면 → [R] 재개 모드.**
- **없으면 → 신규 모드 (0-1).**

### 0-1. 신규 모드 준비

1. **BASE 고정**: `git rev-parse --abbrev-ref HEAD`를 읽어 `BASE`로 기억한다.
2. **워킹트리 청결**: `git status --porcelain`이 비어 있어야 한다. 변경이 있으면 멈추고 보고한다(커밋/스태시 여부 질문).
3. **범위 해석**: `$ARGUMENTS`를 해석한다.
   - **개수형**("5개", "3개 항목") → 그 개수만큼 담는다.
   - **기능 지정형**("xx 기능까지") → 해당 기능을 포괄하는 항목들을 담는다.
   - **전부**("백로그 전부", "다 끝낼 때까지") → 실행 가능한 모든 항목을 담는다.
   - **생략/빈 값** → **자체 결정.** `## 우선순위` 상단에서 한 번의 루프로 무리 없이 끝낼 응집된 범위(보통 서로 연관된 상위 2~4개)를 스스로 정하고, 범위와 근거(속도/종속/임팩트)를 한 줄로 알린 뒤 그대로 진행한다(승인 대기하지 않는다).
   - 명시됐으나 해석이 모호하면 멈추고 한 번만 확인한다.
4. `docs/backlog.md`의 `## 우선순위` 목록을 위에서부터 읽어 범위 항목을 추린다. 각 항목의 상세는 `## 상세`의 **같은 제목** 블록에서 가져온다.
   - **제외**: 보류·미확정·장기 검토 표시 항목.
   - **차단 항목**: 합리적 기본 결정이 가능하면 그 결정을 내려 포함하고, 진짜 불가능하면 빼고 마지막 요약에 남긴다.

### 0-2. 통합 브랜치 생성 + 계획 파일 커밋

1. 범위를 대표하는 슬러그로 `INTEG = loop/<슬러그>`로 둔다.
2. `git checkout <BASE>` 확인 후 `git checkout -b <INTEG>`.
3. 계획 파일 `docs/tdd-loop-plan.md`를 작성한다.

   ```markdown
   # TDD Loop 계획

   - 베이스 브랜치: <BASE>
   - 통합 브랜치: <INTEG>
   - 범위: <원문 $ARGUMENTS 또는 자체 결정 요약>

   ## 항목

   - [ ] 1. <기능 한 문장 요약> — 브랜치: <feat|fix|refactor>/<슬러그> — 머지: -
   - [ ] 2. <기능 한 문장 요약> — 브랜치: <...> — 머지: -
   ```

   - 각 항목은 `/tdd`를 **한 번** 호출해 끝낼 수 있는 단위로 쪼갠다. 항목 수 = tdd 호출 횟수.
4. 계획 파일만 단독 커밋: `git add docs/tdd-loop-plan.md && git commit -m "chore: tdd-loop 계획 수립"`. 다른 변경과 절대 섞지 않는다.

→ [1] 루프로 들어간다.

---

## R. 재개 모드

1. `docs/tdd-loop-plan.md`를 읽어 `BASE`, `INTEG`, 범위, 항목 목록과 각 상태를 복원한다.
2. `git checkout <INTEG>`(없으면 멈추고 불일치를 보고).
3. **중단 지점 진단**: `git status --porcelain`, `git branch --list '*/*'`, `git log --oneline -10`. 반쯤 진행된 항목이 보이면 어디서 이어야 할지 판단한다(불명확하면 멈추고 보고). 깨끗하면 첫 번째 `[ ]` 항목부터 진행한다.

→ [1] 루프로 들어간다 (재계획하지 않는다).

---

## 1. 루프 (모든 `[ ]` 항목이 `[x]`가 될 때까지)

다음 `[ ]` 항목마다 아래를 순서대로 수행한다. 항상 `INTEG` 위에서 시작한다.

### 1-1. 항목 브랜치 분기
`git checkout <INTEG>` 확인 후 계획 파일의 브랜치명으로 `git checkout -b <항목-브랜치>`.

### 1-2. 구현 위임
`/tdd <해당 항목의 기능 요약 한 문장>`을 호출한다. 현재 항목 브랜치 위이므로 tdd가 이 브랜치에서 RED→GREEN→REFACTOR를 돌리고 단계별 커밋한다.
- **tdd가 실패를 보고하면** 즉시 루프를 멈추고 현재 상태와 함께 보고한다. 머지하지 않는다(계획 파일이 남아 재개 가능).

### 1-3. 통합 브랜치로 머지
`git checkout <INTEG>` 후 `git merge --no-ff <항목-브랜치> -m "merge: <기능 요약> (<항목-브랜치>)"` (메시지 한국어).
- **충돌 시**: 자동 해소하지 말고 `git merge --abort` 후 멈추고 보고.
- 머지 후 **검증**으로 통합 상태가 green인지 확인한다. 실패하면 멈추고 보고.
- 통과 시 항목 브랜치 삭제: `git branch -d <항목-브랜치>`.

### 1-4. 백로그 정리 (별도 커밋, INTEG 위)
완료 항목을 `docs/backlog.md`의 `## 우선순위` 줄과 `## 상세` 블록에서 **모두** 삭제한다(순서는 위치 기반이라 재정렬 불필요). 이 변경만 단독 커밋: `git add docs/backlog.md && git commit -m "docs: 백로그 갱신"`. **어떤 항목을 지웠는지 메시지에 언급하지 않는다.**

### 1-5. 계획 파일 갱신 (별도 커밋, INTEG 위)
해당 항목을 `[x]`로 바꾸고 `머지:`에 1-3의 머지 커밋 해시를 기록한다. 단독 커밋: `git add docs/tdd-loop-plan.md && git commit -m "chore: tdd-loop 진행 갱신"`. 백로그 커밋과 섞지 않는다.

### 1-6. 다음 항목
남은 `[ ]`가 있으면 **묻지 말고** 1-1로 돌아가 자동 진행한다. 모두 `[x]`면 [2]로 간다.

---

## 2. 마무리 (모든 항목 완료)

1. **계획 파일 삭제 커밋**(INTEG 위): `git rm docs/tdd-loop-plan.md && git commit -m "chore: tdd-loop 계획 완료 및 정리"`.
2. **BASE로 머지**: `git checkout <BASE>` 후 `git merge --no-ff <INTEG> -m "merge: <범위 요약> tdd-loop 완료 (<INTEG>)"`. 충돌 시 `git merge --abort` 후 멈추고 보고.
3. 머지 후 **검증**으로 최종 green을 확인한다. 실패하면 멈추고 보고.
4. 통과 시 통합 브랜치 삭제: `git branch -d <INTEG>`.

---

## 3. 부수 규칙

- **무관한 버그 발견 시**: 그 자리에서 고치지 않는다. `docs/bugs.md`에 발견 맥락과 함께 기록·별도 커밋(INTEG 위)한 뒤 본 작업을 계속한다.
- 계획 파일·백로그 변경 커밋은 **항상 INTEG 위에서만** 일어난다. 항목 브랜치나 BASE에서 건드리지 않는다.
- 루프는 다음 경우에만 멈춘다: 전체 완료, 실행 가능 항목 없음, tdd 실패, 머지 충돌, 검증 실패, 진짜 차단 항목, 재개 지점 불명확.

---

## 4. 종료 요약

- 완료한 항목 목록과 각 `--no-ff` 머지 커밋 해시.
- 건너뛴/차단된 항목과 이유.
- 종료 사유(전체 완료 / 항목 소진 / 실패로 중단 — 중단이면 재개 방법: 같은 스킬 재호출 시 계획 파일로 이어감).
- 현재 브랜치가 `BASE`이고 워킹트리가 깨끗한지, 통합 브랜치·계획 파일이 정리됐는지.
