백로그를 자동으로 소진하는 오케스트레이터다. 작업 범위: **$ARGUMENTS**

핵심 원리: **항목 하나 = 브랜치 하나 = `--no-ff` 머지 하나.** 모든 항목은 BASE가 아니라 통합 브랜치 `INTEG`(`loop/<슬러그>`) 위에 누적되고, 전부 끝나면 한 번만 BASE로 머지된다. 각 항목의 RED/GREEN/REFACTOR와 커밋은 `/tdd`에 위임한다. 별도의 계획·검수 에이전트는 띄우지 않는다.

- `BASE`: 호출 시점의 브랜치. `INTEG`: 이번 루프의 통합 브랜치.
- **검증**: 프로젝트가 정의한 검증 명령(CLAUDE.md, README, package.json scripts, Makefile, CI 설정 등), 없으면 전체 테스트 스위트.

## 시작

1. 현재 브랜치가 `loop/*`이거나 `loop/*` 브랜치가 남아 있으면 **재개**다(아래). 아니면 신규 시작이다.
2. 신규: 워킹트리가 깨끗해야 한다(아니면 멈추고 보고). 현재 브랜치를 `BASE`로 기억한다.
3. 작업 출처는 `$ARGUMENTS`에 적힌 항목, 아니면 프로젝트 지침(CLAUDE.md 등)이 가리키는 백로그다. 둘 다 없으면 멈추고 묻는다(백로그를 임의로 만들지 않는다).
4. 범위에 맞는 항목을 추려 `/tdd` 한 번으로 끝낼 단위로 쪼갠다. 보류·미확정 항목은 제외한다. 범위가 생략됐으면 우선순위 상단에서 응집된 2~4개를 스스로 정해 한 줄로 알리고 승인 대기 없이 진행한다. 해석이 모호하면 한 번만 확인한다.
5. `git checkout -b loop/<슬러그>`로 `INTEG`를 만든다. 항목 목록은 대화 안에서만 관리한다(파일을 만들지 않는다).

## 루프 (항목마다, 항상 INTEG 위에서)

1. `git checkout -b <feat|fix|refactor>/<항목-슬러그>`.
2. `/tdd <기능 요약 한 문장> (tdd-loop 하위 호출: 발견한 이슈는 이관하지 말고 보고만 한다)` 호출. tdd가 실패를 보고하면 머지하지 않고 멈춰 보고한다.
3. `git checkout <INTEG>` 후 `git merge --no-ff <항목-브랜치> -m "merge: <기능 요약> (<항목-브랜치>)"`(커밋 컨벤션·언어는 기존 `git log`를 따른다). 충돌 시 `git merge --abort` 후 멈추고 보고한다.
4. **검증** 실패 시 멈추고 보고한다. 통과하면 `git branch -d <항목-브랜치>`.
5. 프로젝트 지침이 백로그 갱신 방식을 정해 뒀다면 그대로 처리하고 `INTEG` 위에서 별도 커밋한다. 정해 둔 게 없으면 건드리지 않는다.
6. 남은 항목이 있으면 묻지 말고 다음으로 간다.

무관한 버그를 발견하면 고치지 않고 `발견한 이슈`로 기억해 두었다가 종료 요약에 적는다(지침이 버그 기록 방식을 정했으면 그 방식으로 `INTEG` 위에서 별도 커밋).

## 마무리

`git checkout <BASE>` → `git merge --no-ff <INTEG> -m "merge: <범위 요약> tdd-loop 완료 (<INTEG>)"` → **검증** → `git branch -d <INTEG>`. 충돌이나 검증 실패 시 멈추고 보고한다. push는 하지 않는다.

## 재개

`INTEG`로 체크아웃하고 `git log --merges --format=%s`로 머지된 항목을 파악해 작업 출처의 남은 항목을 다시 추린다. 항목 브랜치가 남아 있으면 그 브랜치에서 `/tdd`를 다시 호출한다(`/tdd`가 자체 계획 파일로 이어받는다). 상태가 서로 어긋나 판단이 안 되면 멈추고 보고한다.

## 멈추는 경우

전체 완료, 실행 가능 항목 없음, tdd 실패, 머지 충돌, 검증 실패, 작업 출처 불명, 재개 지점 불명확일 때만 멈춘다.

종료 시 보고: 완료 항목과 머지 해시, 건너뛴 항목과 이유, 발견한 이슈, 종료 사유(중단이면 같은 스킬 재호출로 재개), 현재 브랜치와 워킹트리 상태.
