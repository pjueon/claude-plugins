# nanobanana

`agy -p "프롬프트"` 형태로 Antigravity CLI를 비대화형 호출하여 nano banana
(Google 이미지 생성 엔진의 코드명)로 이미지를 생성한다. agy는 agentic CLI라서
이미지 생성·저장을 도구 호출로 직접 수행한다 — 따라서 "어디에 무슨 이름으로
저장하라"를 프롬프트로 명확히 지시하는 것이 핵심이다.

## 핵심 규칙

1. **저장 경로·파일명을 항상 명시한다.** 그냥 "이미지 생성해줘"라고만 하면 agy는
   자기가 관리하는 폴더에 저장하고 경로만 알려주는 경향이 있다. 절대 경로 + 파일명을
   프롬프트에 박아 넣고, `--add-dir`로 출력 폴더 쓰기를 허용한다.
2. **비대화형이므로 `--dangerously-skip-permissions`가 필요하다.** 이게 없으면
   agy가 파일 쓰기 권한 승인을 기다리다 멈춘다(print 모드에서 응답 없음).
3. **에러는 삼키지 말고 멈춰서 안내한다.** 미설치 / 로그인 필요 / 할당량 초과 등은
   추측으로 넘어가지 말고 실제 근거(종료코드·로그파일·셸 에러)를 보고 사용자에게 알린다.
4. **설치 여부를 미리 검사하지 않는다.** 개인 환경이라 거의 항상 설치돼 있다.
   `agy --version` 같은 preflight 없이 바로 `agy -p`로 실행하고, 실패하면 그때
   에러 메시지(특히 command not found)로 미설치를 판단한다.
5. **성공 판정은 stdout이 아니라 "출력 파일 존재"로 한다.** agy는 print 모드에서
   이미지를 도구 호출로 저장한 뒤 종료 신호 없이 `--print-timeout`(기본 5분)을
   다 채우고 **빈 stdout으로 반환**하는 경우가 흔하다. 그래서 stdout 파싱에 의존하면
   "이미 끝난 작업을 최대 5분 헛기다리는" 문제가 생긴다. → **백그라운드 실행 +
   출력 파일 폴링**으로 파일이 생기는 즉시 성공 처리한다(아래 워크플로 참조).

## 워크플로

### 1. 출력 경로 결정

- 출력 디렉터리·파일명을 **절대 경로**로 확정한다. 사용자가 지정하지 않았으면
  현재 작업 디렉터리(예: `./generated/<설명>.png`)를 기본값으로 제안한다.
- 출력 디렉터리가 없으면 미리 만든다 (`mkdir -p`). agy가 폴더를 만들어주리라
  가정하지 않는다.
- 확장자는 보통 `.png`. 사용자가 다른 포맷을 원하면 그에 맞춘다.

### 2. 백그라운드로 실행하고 출력 파일을 폴링한다

agy에게 줄 프롬프트에는 **(1) 무엇을 그릴지 (2) 정확한 저장 경로**를 모두 넣는다.
그리고 **agy를 백그라운드로 띄운 뒤, 지정한 출력 경로에 파일이 생기는지 폴링**한다.
agy의 종료를 기다리지 않는 이유는 위 핵심 규칙 5번 참조(print 모드가 빈 stdout으로
최대 5분 매달리는 문제).

권장 플래그:
- `--print-timeout 3m` — 헛기다림 상한을 줄인다(기본 5분 → 3분).
- `--log-file "<ABS_LOG_PATH>"` — stdout이 비어도 진단할 수 있게 로그를 파일로 남긴다.
  로그 경로는 출력 디렉터리나 임시 폴더(예: `<출력 디렉터리>/.agy.log`)로 둔다.

**텍스트만으로 생성** (셸 도구의 `run_in_background: true`로 실행):
```bash
agy -p "다음 이미지를 생성해줘: <사용자 묘사>. 생성한 이미지를 반드시 정확히 이 경로에 저장해: <ABS_OUT_PATH>. 다른 폴더에 저장하지 말고 이 경로와 파일명을 그대로 사용해." \
  --add-dir "<출력 디렉터리>" \
  --dangerously-skip-permissions \
  --print-timeout 3m \
  --log-file "<ABS_LOG_PATH>"
```

**입력 이미지를 참고/편집해서 생성:**
입력 이미지의 절대 경로를 함께 전달하고, 그 폴더도 `--add-dir`로 추가해 agy가 읽을 수
있게 한다.
```bash
agy -p "이 입력 이미지를 참고/편집해서 새 이미지를 만들어줘. 입력: <ABS_IN_PATH>. 변경 요청: <사용자 묘사>. 결과는 반드시 정확히 이 경로에 저장해: <ABS_OUT_PATH>." \
  --add-dir "<입력 디렉터리>" \
  --add-dir "<출력 디렉터리>" \
  --dangerously-skip-permissions \
  --print-timeout 3m \
  --log-file "<ABS_LOG_PATH>"
```

폴링 방법:
- agy를 백그라운드로 띄운 직후부터 `<ABS_OUT_PATH>` 존재 여부를 몇 초 간격으로 확인한다.
  파일이 생기고 **크기가 한 번 이상 안정(같은 크기 유지)되면 완성**으로 보고 즉시 성공 처리한다.
  agy 프로세스가 끝나길 기다릴 필요 없다.
- 합리적 상한(예: 약 3~4분) 안에 파일이 끝내 안 생기면, 그때 `--log-file`과 셸
  에러를 읽어 실패 원인을 판단한다(아래 결과 처리 참조).

실행 팁:
- 프롬프트 안에 따옴표가 섞이면 인용이 깨질 수 있다. 사용자 묘사에 큰따옴표가 있으면
  바꿔 쓰거나 다른 인용 방식을 쓴다. 경로는 절대 경로를 그대로 쓴다.
- **이미지 크기를 픽셀 단위로 지정할 수 있다.** 원하는 해상도가 있으면 프롬프트에
  가로·세로를 명시한다(예: `1024x1024 px로 생성`, `가로 1920px 세로 1080px`).

### 3. 결과 처리

판정의 1차 근거는 **출력 파일 존재 여부**다. stdout은 비어 있는 게 정상일 수 있으므로
믿지 않는다.

**(a) `<ABS_OUT_PATH>`에 파일이 생겼으면 → 성공.** 그 경로를 사용자에게 알려주고 끝.
agy 프로세스가 아직 안 끝났어도 폴링에서 파일+안정 크기를 확인했으면 그대로 보고한다
(백그라운드 프로세스는 곧 print-timeout으로 알아서 종료된다).

**(b) 상한 시간 안에 파일이 안 생겼으면 → 멈추고 안내한다.** `--log-file` 내용과
셸 에러에서 다음 단서를 찾는다:
- 미설치(`command not found`, `agy : ...is not recognized`, 셸이 명령을 못 찾음)
  → "Antigravity CLI(`agy`)가 설치되어 있지 않은 것 같습니다. 설치 후 다시 시도해 주세요."
- 로그인/인증 관련(`login`, `auth`, `unauthorized`, `OAuth`, 401 등)
  → "Google 로그인이 필요합니다. `agy`로 로그인 후 다시 시도해 주세요."
- 할당량/쿼터(`quota`, `rate limit`, `limit exceeded`, `429` 등)
  → "오늘 이미지 생성 할당량을 초과한 것으로 보입니다. 잠시 후/내일 다시 시도해 주세요."
- 그 외 실패 → 로그파일의 원문을 그대로 인용해서 사용자에게 보여준다. 무엇이
  실패했는지 추측으로 단정하지 말 것.

**(c) 다른 위치에 저장된 경우.** 파일이 `<ABS_OUT_PATH>`에는 없지만 로그에 다른 저장
경로가 보이면(agy가 자기 관리 폴더에 저장하고 경로만 남긴 경우), 그 파일을
`<ABS_OUT_PATH>`로 복사/이동한 뒤 최종 경로를 알린다. 위치를 끝내 못 찾으면 로그를
그대로 보여주고 사용자에게 확인을 요청한다.

## 정밀 제어: 구조화된(JSON) 프롬프트

핵심은 원하는 바를 **JSON처럼 AI가 이해하기 쉬운 구조화된 형식으로 명시적으로 지정**하는 것.
자연어 나열보다 정확히 반영된다. 두 가지 팁:

1. **정보를 JSON으로 구조화한다.** 스타일·색상·조명·객체·구도 등 이미지의 특징을
   구조화된 JSON으로 정리해 프롬프트에 함께 넣는다. 이 JSON은 Claude가 직접 작성하거나,
   입력 이미지를 `agy -p`로 Gemini에게 분석시켜 만들 수 있다.
   - 활용: 레퍼런스 이미지의 촬영 기법·조명·구도를 JSON으로 뽑아, 같은 스타일로 새
     이미지를 생성한다.

2. **바꿀 것보다 유지할 것을 명시한다(surgical change).** 이미지의 일부만 수정할 때
   "무엇을 바꿔라"만 말하면 나머지 요소도 함께 변할 수 있다. 전체를 JSON으로 정리한 뒤, **수정할 필드만 바꾸고 유지해야 할 나머지 필드는 그대로 명시**해서 이미지와 함께
   전달한다. 유지 요소를 명시적으로 지정할수록 가중치가 실려 원치 않는 변형을 막는다.

## 출력은 간결하게

작업 결과는 최종 이미지 경로 한 줄로 명확히 전달한다. agy의 장황한 agentic 로그를
그대로 사용자에게 쏟지 말고, 필요한 부분(에러 원문, 실제 저장 위치)만 인용한다.
