# 장 집필과 점검

## 장 하나를 쓰는 순서

1. **커리큘럼에서 그 장의 항목 · 화면 수 · 시간을 확인한다.** 화면 수는 지키는 것이 좋다.
2. **앞장이 미뤄 둔 것을 확인한다.** 앞장에 `.later` 로 "N장에서 본다"고 적어둔 것,
   커리큘럼의 "앞장에서 받는 것". 아직 다루지 않은 것이 있으면 이 장에서 다룬다.
3. **코드가 누적되는 교재면 `authoring/02-코드-정본.md` 를 먼저 연다.** 본문 코드는 정본을 따른다.
4. **화면 목록을 먼저 적고**(제목 + 한 줄), 그 다음에 본문을 쓴다.
   화면 개수가 커리큘럼과 다르면 그 이유를 커리큘럼에 반영한다.
5. `ch-template.html` 을 복사해 쓴다. 없는 마크업은 만들지 않는다.
   수식은 LaTeX `\( \)`·`\[ \]` 로 쓴다(SKILL.md "수식" 절). 코드 식별자는 `<code>`.
6. **`book.js` 의 `BOOK` 에 이 장의 `ready: true` 와 실제 화면 수를 반영한다.**
7. 점검(아래)을 돌린다.

## 점검 — 두 명령

브라우저 경로 예: `/c/Program Files/Google/Chrome/Application/chrome.exe`
(Edge 도 된다. `--headless=new` 를 지원하는 크로미움이면 무엇이든)

### 1) 런타임 점검 — `_smoke.html`

53개 단정(사이드바, 화면 이동, 카운터·진행률·주소 `#sN`, 하이라이터 토큰, 부등호 보존, 탭, 수식 렌더(KaTeX),
퀴즈 채점·키보드 조작, 용어 툴팁 `#tip`, 화면 참조 링크·돌아가기).
**`book.css` · `book.js` 를 고칠 때마다 돌린다.**

```bash
chrome --headless=new --disable-gpu --no-sandbox --virtual-time-budget=4000 \
  --dump-dom "file:///<authoring 절대경로>/_smoke.html" > out.html
# out.html 의 <pre id="test-out"> 에서 FAIL 이 0 인지 확인
```

`_smoke.html` 의 단정은 `BOOK` 구조에 묶이지 않게 쓴다(장 수를 하드코딩하지 말 것).
`TERMS` 의 `_smoke` 항목은 이 파일이 참조하므로 지우지 않는다.

### 2) 새 장 점검 — 임시 probe

장 파일 **사본**에 아래를 붙여 모든 화면을 켜고 검사한다. 확인할 것: 코드 블록 가로 넘침
(1280px 기준 0), 화면 수, 툴팁 미연결 개수(`TERMS` 에 없는 `data-term`).

```javascript
// chNN.html 사본의 </body> 앞에 붙인다
window.addEventListener('load', function () {
  var res = [], scs = document.querySelectorAll('.screen');
  for (var i = 0; i < scs.length; i++) {
    scs[i].classList.add('is-active');
    var pres = scs[i].querySelectorAll('pre');
    for (var j = 0; j < pres.length; j++) {
      var over = pres[j].scrollWidth - pres[j].clientWidth;
      if (over > 1) res.push('s' + (i + 1) + 'pre' + (j + 1) + '=' + over);
    }
    scs[i].classList.remove('is-active');
  }
  var box = document.createElement('pre'); box.id = 'probe-out';
  box.textContent = (res.length ? 'OVERFLOW ' + res.join(',') : 'NO-OVERFLOW')
    + ' screens=' + scs.length
    + ' termsMissing=' + document.querySelectorAll('.term:not([data-def])').length
    + ' katexError=' + document.querySelectorAll('.katex-error, .katex-html [style*="rgb(204, 0, 0)"]').length
    + ' rawMath=' + (function () {
      var c = document.getElementById('book').cloneNode(true);   // 렌더되지 않고 남은 \( \[ 가 있는지
      Array.prototype.forEach.call(c.querySelectorAll('pre, code, .katex, svg, script'), function (e) { e.remove(); });
      return /\\\(|\\\[/.test(c.textContent) ? 1 : 0;
    })();
  document.body.appendChild(box);
});
```

`--window-size=1280,1250 --dump-dom` 으로 열고 `<pre id="probe-out">` 를 읽는다.
기대값은 `NO-OVERFLOW screens=<커리큘럼의 화면 수> termsMissing=0 katexError=0 rawMath=0`.
`katexError` 는 LaTeX 오류(문법 오류, 또는 정의되지 않은 명령이라 빨간 글자로 나온 것), `rawMath` 는 렌더되지 않고 `\(` 가 그대로 남은 곳이다(스크립트 순서 오류, 또는 중괄호 `{ }` 짝이 안 맞는 식 — 이 경우는 오류 표시 없이 원문이 그대로 보인다).
오류가 나오면 `.katex-error` 의 `title` 속성에 KaTeX 오류 메시지가 있고, 빨간 글자는 그 글자가 곧 틀린 명령이다.
수식 내용(숫자·부호)이 맞는지는 이 점검이 못 본다 — 검수에서 직접 계산한다.
가로 넘침이 나오면 **코드 줄을 줄인다**(본문 폭 45rem, 코드 폰트 .82rem → 약 90자).
레이아웃을 넓히는 방향으로 대응하지 않는다.

probe 의 `NO-OVERFLOW` 는 `<pre>` 만 본다. **페이지 자체의 가로 스크롤**은 따로 본다 —
화면마다 `is-active` 를 돌리면서 그 화면의 `.term[data-def]` 마다 `mouseover` 를 보내고,
`document.documentElement.scrollWidth > clientWidth` 인지 확인한다. 본문에 넣은 표·그림·위젯이
넓어도 여기서 잡힌다. (툴팁은 `book.js` 가 body 에 붙인 `#tip` 하나를 화면 안에 맞춰 띄운다.
예전 `.term::after` 방식은 숨겨져 있어도 레이아웃에 남아 줄 끝에서 페이지 가로 스크롤을 만들었다.)

## 다른 화면을 인용할 때

`book.js` 가 본문 텍스트에서 다음을 자동으로 링크로 바꾼다(마크업 불필요).
`<code>`·`<pre>`·이미 링크인 곳·`kicker`·그림(`svg`) 안은 건드리지 않는다.

- **"화면 N"**(같은 장) — 누르면 그 화면으로 바로 이동하고, 하단에 돌아가기 버튼이 뜬다. "화면 4·6", "화면 2~3" 처럼 이어 쓴 번호도 각각 링크가 된다.
- **"N장 화면 M"** — `chNN.html#sM` 링크. `ready` 인 장만 링크가 된다. 누르면 그 장으로 이동하고
  이동한 쪽에 돌아가기 버튼이 뜬다.
- 링크로 만들면 안 되는 자리(번호가 다른 뜻인 경우)는 `<code>` 로 감싼다.

그래서 집필할 때는:

1. 같은 장의 "화면 N" 은 그냥 쓴다. 단, **본문 논증이 그 표·그림을 보면서 따라가야 하면** 그 자리에
   작게 다시 보인다(`.box.note` 에 "다시 보기").
2. **다른 장의 내용**을 근거로 쓸 때는 괄호 한 줄 요약을 붙이거나 다시 보인다.
3. **퀴즈·과제가 앞 화면의 표·코드를 전제하면** 그 표를 문제 옆에 다시 보인다. 정답이 드러나는 재게시는 하지 않는다.

## 한국어 문체

집필자는 쓰면서, 리뷰어는 검수하면서 같은 기준을 쓴다. 사용자가 직접 지적한 어색함이 기준이다 — 번역 느낌, AI 같은 과장,
어색한 섹션명, 이해하기 어려운 설명. 존댓말('~합니다')과 의미는 유지하고, 필요 이상으로 문체를 바꾸지 않는다.

**섹션명(h2·h3·박스 제목·`summary`·`data-title`)**
- 명사구로 끝낸다. "내적의 의미", "모범답안과 흔한 실수".
- 서술문("내적이 재는 것", "부호로 어느 쪽인지 안다"), 구어 질문("왜 굳이 다시 쓰나", "이 문제를 어떻게 푸나?"), 대구("엄격할 것인가, 관대할 것인가")는 쓰지 않는다.
- '그래서·그런데·그리고·이제'로 시작하지 않는다. 한 제목에 두 주제를 대시로 잇지 않는다.
- 단계 제목은 한 형태로 통일한다(전부 "~하기" 또는 전부 서술형).

**번역투·직역 은유 — 평이한 말로 푼다**
- 직선·데이터에는 '가르다/갈리다' 대신 '분류하다·구분하다·분리하다·나누다'. '맞히다/틀리게 두다'는 '올바르게 분류하다/잘못 분류하다·오분류하다'.
- '못 박다→고정하다·정하다', '대 보다→적용하다·대입하다', '~에 의해→~에서·~이므로', '~의 몫→~에서 다룹니다', '비싼 값을 치르다→비용이 늘어납니다'.
- 교재 은유('교재의 허리·심장·뼈대·씨앗·열쇠', '아픔', '맛보기', '길', '그릇 모양', '손에 쥐는 것')는 쓰지 않는다. 핵심은 "가장 중요한 파트"처럼 직접 쓴다.
- 의인화('욕심·힘을 쓴다·밀어낸다·알아서 정한다·허락한다')와 감정어는 뜻을 직접 쓴다. "제약이 작용한다", "균형을 이룬다".
- 수학 용어를 정확히 쓴다: 두 식을 더해 사라지면 '상쇄'(약분 아님), '가능해', '최댓값·최솟값'(사이시옷).

**AI 같은 말투**
- '정직하게·솔직히', 문단 머리의 짧은 단정문("힘의 균형입니다."), '~의 이야기입니다', "A 하는 대신 B 를 치르게 합니다" 같은 대구, 과장('폭발', '낭떠러지', '완성')을 줄인다.
- 한 문장에 한 주장. "이유는 ~라서 ~때문입니다" 같은 이중 인과, 명사 나열로 끝나는 서술, 쉼표로 판단을 5개 이상 잇는 문장은 나눈다. 수식은 문장 중간을 끊지 않게 문장 끝이나 별도 줄에 둔다.

**일관성·표기**
- 같은 개념은 한 용어로("크기를 고정한다"로 통일). 본문·표·퀴즈 해설은 '~합니다' 체로 맞춘다(요약 박스처럼 의도한 곳만 예외).
- '해 보기'(띄어쓰기), 조사는 읽는 소리 기준: x⁽³⁾ 은(삼), ‖w‖² 은(제곱).
- 직선·점에 가·나·다·라 같은 이름을 붙이면 문장 안에서 "‘나’ 직선은"처럼 따옴표와 '직선'을 붙인다(대명사 '나'와 구분). 장이 달라 같은 이름이 다른 대상이면 장마다 맥락을 밝힌다.
- 같은 사실을 다른 장·화면에서 인용할 때는 현재 문구와 맞춘다(버튼 이름, 박스 제목).

**분량** — 한 화면에 새 개념이 대략 4개를 넘고 뒷부분이 앞보다 훨씬 추상적이면(증명·일반화 등) 선택 읽기 부분을
`details.fold` 접는 상자로 옮기고, 접기 앞뒤에 "이 부분은 건너뛰어도 된다 / 뒤에서는 결과만 쓴다" 연결 문장을 둔다. 화면 수를 늘리면 `kicker`·"화면 N" 참조·`BOOK` 을 모두 다시 맞춰야 하니 먼저 접기를 고려한다.

## 자주 틀리는 것

1. **코드 해설의 행 번호 어긋남** — 가장 자주 틀린다. `ol.notes` 를 쓸 때마다 실제 코드와
   대조한다. 코드를 한 줄 고치면 그 아래 모든 번호가 밀린다.
2. **화면을 중간에 끼워 넣기** — `kicker` 번호, 주석 구분선 번호, 본문의 "화면 N" 상호 참조,
   `BOOK` 의 `screens` 값을 모두 다시 매긴다.
   `grep -n "화면 [0-9]" docs/chNN.html | grep -v kicker` 로 남은 참조를 확인한다.
   참조가 자동 링크가 되었다고 번호가 맞는 것은 아니다 — 링크가 가리키는 화면에 인용한 표·수치가 실제로 있는지 본다.
3. **`TERMS` 에 없는 `data-term`** — 툴팁이 조용히 안 나온다. probe 의 `termsMissing` 이 잡는다.
4. **`ready: true` 를 안 켜서** 목차에서 새 장이 회색으로 남는 것.
5. **`.later` 로 표시만 하고 안 다루는 것.** 표시한 장에서 반드시 다룬다.
   `.later` 문구와 본문에는 "갚는다·빚" 같은 비유를 쓰지 않는다(어색한 번역투).
   "N장에서 다룹니다 / N장에서 다룸", "약속을 지킵니다", "미뤄 둔 질문" 처럼 쓴다.
   (장부·기획 같은 작업 문서의 "갚을 장" 은 내부 용어라 그대로 둬도 된다.)
6. **용어를 정의하기 전에 쓰는 것.** 이름이 붙은 화면보다 뜻을 설명하는 화면이 앞에 와야 한다.
   집필 후 `grep` 으로 첫 등장 위치를 확인한다.
7. **부등호를 이스케이프하지 않은 것** — `pre` 안에서 `<` `>` 는 `&lt;` `&gt;` 로 쓴다.
8. **일괄 치환으로 수식이 깨지는 것** — 파이썬 등으로 본문을 치환할 때 일반 문자열 안의 `\tfrac`·`\text`·`\theta` 의 `\t` 가
   탭 문자로 바뀌어 수식이 조용히 깨진다. 치환 문자열은 raw 로 쓰고, 끝나면
   `grep -nP "[\x00-\x08\x0b\x0c\x0e-\x1f]" docs/chNN.html` 이 0건인지 확인한다. 코드 블록(`pre`)은 의도한 변경 외에 diff 가 없어야 한다.

## 진도 저장 주의

`file://` 에서는 로컬로 열린 모든 페이지가 `localStorage` 를 공유한다.
`book.js` 의 `STORE_KEY` 를 교재마다 다른 접두어로 둔다(예: `ddd-book:progress`).
같은 블록의 `NAV_KEY`·`BACK_KEY`(`sessionStorage`)도 같은 접두어로 바꾼다.

완독(✓)은 직전 화면에서 '다음'으로 마지막 화면에 왔을 때만 남는다. `#sN` 딥링크나 목차 클릭으로
마지막 화면을 열어 본 것은 완독이 아니다. '다음 장'으로 넘어가면 그 장은 항상 화면 1부터 열린다.
