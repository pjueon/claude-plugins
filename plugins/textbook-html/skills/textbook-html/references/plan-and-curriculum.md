# 기획서와 커리큘럼 — 서식과 배분 기준

집필 전에 만드는 두 문서다. `authoring/00-기획.md`, `authoring/01-커리큘럼.md` 로 저장한다.
둘 다 **결정을 적는 문서**다. 선택지를 나열하고 끝내지 않는다.

---

## 1. 기획서 (`00-기획.md`)

완료 기준은 하나다 — **이 문서만 보고 다른 사람이 5장을 쓸 수 있는가.**

```markdown
# <주제> 학습 교재 제작 기획서

## 1. 목적과 대상 독자
- 목적: 무엇을 할 수 있게 만드는 교재인가. "블로그 글 모음이 아니라 한 권의 책"
- 독자가 **전제하지 않아도 되는 것**: (모른다고 가정할 지식을 낱말 단위로 나열)
- 독자가 **전제해도 되는 것**: (설명 없이 써도 되는 지식)

## 2. 학습 목표
다 읽은 뒤 독자가 할 수 있어야 하는 것 5~7개. 각 항목은 "…할 수 있다" 로 끝난다.
마지막 항목은 되도록 **"이 기술을 쓰지 말아야 할 때를 판단할 수 있다"** 로 둔다.

## 3. 관통 예제
교재 전체를 하나의 예제로 관통한다. 장마다 예제가 바뀌면 앞장의 코드가 뒷장에서
쓸모없어지고, 독자는 매번 새 맥락을 이해하는 데 힘을 쓴다.
- 예제의 설정과 **그 설정을 고른 이유**(이 주제의 문제가 자연스럽게 발생하는가)
- 등장인물(있으면): 역할과 그들이 쓰는 낱말
- 용어표: 낱말 | 뜻 | 무엇과 다른가  ← 세 번째 칸이 핵심이다
- 교재 중반에 들어올 **새 요구사항**을 미리 정해 둔다. 초반에는 없던 요구가 들어와야
  독자가 "왜 구조가 필요한가"를 겪는다.
- 의도적으로 미뤄둘 것과 그것을 **몇 장에서 갚을지**

## 4. 형태 — 결정 사항
- 장 = HTML 파일 1개, 장 안은 화면(screen) 단위. (이유는 skill 의 R1)
- `file://` 제약과 그에 따른 기술 선택 (fetch/module/CDN 금지)
- 넣을 인터랙티브 요소와 **넣지 않을 것**

## 5. 서술 방침
- 개념 → 이름 순서. 문제와 코드를 먼저 보이고 이름은 나중에.
- (코드를 다루는 주제라면) 1장을 **나쁜 코드/틀린 방식**으로 시작하는 것이 잘 통한다.
  아픔을 겪고 해법을 배우는 순서다. 주제에 따라 안 맞으면 쓰지 않는다.
- 코드 해설 원칙: 20줄 넘으면 `ol.notes`, 낯선 관용구는 처음 나오는 자리에서,
  업무 용어는 코드보다 먼저, 구조(스키마·전체 그림)는 코드보다 먼저.
- 원전 표기: 개념의 출처를 밝혀 독자의 다음 책을 가리킨다.
- 반대 의견도 쓴다.

## 6. 분량 목표
장 수 / 장당 화면 / 총 시간.
```

## 2. 커리큘럼 (`01-커리큘럼.md`)

장별로 **항목 · 화면 수 · 시간**을 적는다. 이 세 값이 집필의 계약이다.

```markdown
### N장 — 제목
- **화면 N · N.N시간**
- 다룰 것: (화면 하나에 대응하는 항목으로 쪼개 적는다)
- 이 장이 답하는 질문: (한 줄)
- 앞장에서 받는 것 / 뒷장에 넘기는 것
```

### 배분 기준

- **화면 하나 = 의미 하나.** 스크롤 두세 번에 읽히는 양. 넘치면 화면을 쪼갠다.
- **화면당 10~12분**으로 시간을 잡는다(퀴즈·과제 포함). 12화면 ≈ 2.5시간.
- 한 장이 **17화면**을 넘으면 장을 쪼갠다. **6화면** 미만이면 앞뒤 장에 합친다.
- 개념의 허리가 되는 장(전체의 3~4개)에는 화면을 더 준다. 응용 장은 짧게.
- 마지막 화면은 항상 **요약 · 퀴즈 · 과제**다. 화면 수에 포함한다.
- 전체 시간이 정해져 있으면(예: "주 5시간 × 7주 = 35시간") 그 안에서 장을 정한다.
  총 시간을 넘기면 장을 줄이는 것이 아니라 **선택 장**으로 표시한다.
- 표지의 학습 트랙(주당 시간 → 몇 주)은 이 합계에서 계산한다.

### 코드가 장을 넘어 누적되는 교재라면

`authoring/02-코드-정본.md` 를 하나 더 둔다. 장별로 나눠 쓰다 보면 같은 클래스의
필드명·시그니처가 3장과 7장에서 어긋나는데, "코드가 누적된다"고 약속한 교재에서
그 불일치는 독자가 가장 먼저 알아채는 결함이다.

- 체크포인트(예: 3장 후 · 5장 후 · 7장 후)마다 클래스·메서드 시그니처를 고정한다.
- 각 장을 쓸 때 이 파일을 열어놓고 쓴다. 본문과 어긋나면 **정본이 옳다.**
- 정본을 고쳤으면 그 결정을 표로 남긴다(무엇을 왜 바꿨는지, 반영된 장).
