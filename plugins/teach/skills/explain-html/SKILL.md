# explain-html — 단일 HTML 설명문

**대상:** $ARGUMENTS  *(PR 번호·URL, 커밋 SHA, 브랜치, 이슈, 개념·알고리즘 이름 등)*

목표는 하나다 — **혼자 읽어도 이해되는 설명문 한 편.** 처음 보는 사람이 배경부터 따라
읽고, 끝에서 퀴즈로 이해했는지 확인한다. 설명이 명확하고 흐름이 매끄러운 고전적 문체로
쓰고, 절과 절 사이에는 전환 문장을 둔다. 코드 diff 가 아닌 대상(버그, 알고리즘, 현상)도
같은 뼈대로 쓴다. 한국어 존댓말로 쓴다(코드·식별자 인용은 원문 그대로).

## 규약 E1~E7

- **E1 자체 완결 단일 HTML.** `templates/explain.html` 을 복사해 시작한다. CSS·JS 는
  인라인이고 `file://` 로 열려야 한다. CDN·외부 폰트·`fetch`·`type="module"` 을 쓰지 않는다
  (textbook-html R2 와 같은 제약). 수식 라이브러리는 없다 — 간단한 식은 `<sub>`·`<sup>` 로
  쓰고, 수식이 많으면 textbook-html 을 제안한다(E7).
- **E2 지어내지 않는다.** 본문의 수치·출력·트레이스·toy 예시의 결과는 이번 세션에서 실행한
  명령의 출력에서 가져온다. 얻지 못한 것은 "확인하지 못함"이라고 쓴다. 계산용 스크립트는
  scratchpad 에 두고 대상 저장소에는 두지 않는다. 수치마다 출처 명령을 짝지은 **근거 메모**를
  scratchpad 에 적어 둔다(산출물에는 넣지 않고, 점검 때 대조한다).
- **E3 절 뼈대는 고정이다.** 배경 → 핵심 직관 → 상세 → 퀴즈. 상세 절의 이름과 구성만 대상
  종류에 따라 달라진다(`references/sources.md`).
  - **배경**: 초심자용 깊은 배경은 접어서 "이미 아시면 건너뛰세요"로 둔다. 그 뒤에 이 주제에
    직접 관련된 좁은 배경을 쓴다. 주변 코드·문서를 넓게 읽고 쓴다.
  - **핵심 직관**: 세부가 아니라 본질. 구체적인 toy 예시와 그림을 쓴다.
  - **상세**: 변경이면 코드를 이해하기 좋은 순서로 묶어 훑고, 버그면 원인을 추적하고,
    개념이면 동작을 단계별로 따라간다.
- **E4 그림은 HTML·SVG 로.** ASCII 도식을 쓰지 않는다. 도식 계열은 1~3개만 정해 재사용하고
  도식에는 예시 데이터를 넣는다. 도식·위젯에 필요한 CSS 클래스는 템플릿 `<style>` 끝에 추가해도 된다(색은 변수로). 코드는 반드시 `<pre>` 에 넣는다. 값을 움직여 보일 것이
  있으면 위젯을 만든다 — 지침은 `../../shared/visuals.md` 를 따른다.
  핵심 개념·정의·엣지 케이스는 콜아웃(`.box`)으로 눈에 띄게 한다.
- **E5 문체.** `../../shared/writing-style.md` 를 따른다
  (섹션명은 명사구, 번역투·은유·의인화·AI 말투 금지, 한 문장에 한 주장). 섹션명 규칙은 h2·h3·콜아웃 제목에 적용하고, 템플릿이 정한 접는 배경의 summary 문구는 그대로 둔다.
- **E6 퀴즈.** 5문, 중간 난이도, 함정 없는 객관식이다. 본문의 실질을 이해해야 풀리되
  꼬아 묻지 않는다. 모든 선택지에 `data-why`(왜 맞고 왜 틀리는지)를 달고 정답 위치를
  고르게 섞는다. **마크업은 textbook-html 의 퀴즈와 같은 계약**이다
  (`../../shared/quiz.md`) — 템플릿의 `initQuiz`·퀴즈 CSS 는 `textbook-html/templates/assets` 의 사본이다.
  `.qn` 은 비워 두면 런타임이 "퀴즈 N" 을 넣는다.
- **E7 분량은 한 번에 읽을 만큼(15~25분).** 읽는 시간은 본문 글자 수(접힌 배경 포함, 코드 제외)를 분당 약 500자로 나누고 퀴즈 시간을 더해 어림한다. 넘칠 것 같거나 선행지식 사슬이 길거나 퀴즈 5문으로
  부족하면 아래 "textbook-html 연계"를 따른다.

## 절차

1. **대상 판정과 근거 수집** — `references/sources.md`. 모호하면 한 번만 묻는다.
2. **개요 작성.** 절마다 한 줄 요지, 도식 계열, 퀴즈 5문을 어디서 낼지를 정한다.
   이 시점에 분량과 textbook-html 연계 여부를 판단한다.
3. **파일 만들기.** 출력 위치(아래)에 `templates/explain.html` 을 복사하고 `▣` 자리를 채운다.
   템플릿 안내 주석은 채우면서 지운다. 템플릿은 이 스킬 폴더 기준 `templates/` 에 있다.
4. **점검** — `references/checklist.md`. 통과 못 했으면 통과했다고 쓰지 않는다.
5. **열고 보고한다.** 브라우저로 열고(실패해도 경로를 알린다), 경로·읽는 시간·근거 요약,
   근거를 얻지 못한 부분, 사소한 결정을 한 문단으로 보고한다.

## 출력 위치와 파일명

- 기본은 `~/.claude/explanations/YYYY-MM-DD-<slug>.html` — 저장소 밖의 전역 폴더라 버전
  관리에 섞이지 않고 날짜순으로 정렬된다. 폴더가 없으면 만든다. 날짜는 `date +%F`.
- slug 는 ASCII `[a-z0-9-]` 50자 이내. 한글 주제는 영문으로 옮긴다(다익스트라 → `dijkstra`).
  변경 대상은 `commit-<sha7>-…`, `pr-<n>-…`, 이슈는 `issue-<n>-…`. 같은 이름이 있으면
  덮어쓰지 않고 `-2` 를 붙인다.
- 인자로 출력 경로와 날짜를 바꿀 수 있다.
- Windows 에서 Write 도구에는 절대경로가 필요하다. `cygpath -w` 로 변환해 쓰고, 여는 명령은
  Git Bash `start "" "<경로>"`, PowerShell `Start-Process`, macOS `open`, Linux `xdg-open` 이다.
  GUI 가 없는 환경이면 경로와 `file:///` URL 만 알린다.
- 사용자가 **공유용**이라고 하면 같은 HTML 을 Artifact 로 게시한다. 기본은 아니다.

## textbook-html 연계 (선택)

한 페이지를 넘길 분량이거나, 선행지식을 여러 단계로 쌓아야 하거나, 수식이 많거나, 퀴즈 5문으로
이해 확인이 부족하면 **사용자에게 한 줄로 제안**한다. 확인을 받은 뒤에만 Skill 도구로
`teach:textbook-html` 을 부른다(임의로 전환하지 않는다). textbook-html 은 현재 폴더에
`docs/`·`authoring/` 을 만들므로, 제안할 때 **교재를 만들 폴더**(코드 저장소 안이면 새 학습
폴더를 권한다)도 함께 확인한다. 넘길 때는 지금까지 모은 주제·근거 요약을 전달한다.
짧은 설명이면 textbook-html 을 부르지 않는다.

## 하위 에이전트

기본은 메인이 근거 수집과 집필을 직접 한다. 코드 탐색 범위가 넓으면 Explore 에 맡겨도 된다.

## 동봉 파일

| 파일 | 무엇 |
|---|---|
| `templates/explain.html` | 자체 완결 골격 — 목차·접는 배경·콜아웃·diff 줄 색·퀴즈·단계 위젯 예시 |
| `references/sources.md` | 대상 종류별 근거 수집 방법, 실패 처리, 상세 절 구성 |
| `references/checklist.md` | 저장 전 점검 — probe 스크립트, 내용 점검 |
| `../../shared/` | teach 스킬 공통 기준 — `writing-style.md`(문체), `visuals.md`(그림·위젯), `quiz.md`(퀴즈 계약) |

## 비목표

- **대상 저장소에 파일을 만들거나 커밋하지 않는다.** 코드를 고치지 않는다.
- **호출 시점을 강제하지 않는다** — 훅·워크플로 단계로 배선하지 않는다.
- **여러 장짜리 교재를 만들지 않는다** — 그것은 `teach:textbook-html` 이다.
