# 문항 — 유형, 채점 기준, 코드 문항

## 1. 유형

한 세션에서 대상에 맞는 유형을 섞는다. 코드가 없는 대상(A·C 의 이론)은 1~2 를 중심으로 한다.

| # | 유형 | 묻는 방식 | 채점 |
|---|---|---|---|
| 1 | **개념 설명** | "이 개념을 처음 듣는 동료에게 두세 문장으로 설명해 보세요" | 요점 대조 |
| 2 | **비교·트레이드오프** | "A 대신 B 를 쓰는 상황은 언제인가요? 대가는요?" | 요점 대조 |
| 3 | **코드 동작 설명·출력 예측** | 10~20줄 코드를 보여 주고 "출력은? 왜?" / "이 함수가 하는 일은?" | **실행한 출력**과 대조 + 이유 요점 |
| 4 | **빈칸 채우기** | 핵심 1~3줄을 `/* ___ */` 로 지운 파일을 주고 채운 뒤 왜 그렇게 썼는지 설명 | 테스트 통과 + 설명 요점 |
| 5 | **버그 찾기** | 일부러 하나를 틀리게 만든 코드 + 증상 | 원인 지목 + 고친 코드 테스트 통과 |
| 6 | **직접 구현** | 시그니처·요구사항·실패하는 테스트를 준 작은 함수 | 테스트 통과 + "왜 이렇게 짰나요" 꼬리질문 |

코드 문항(4~6)도 마지막에는 반드시 **설명**을 받는다. 테스트만 통과하고 이유를 말하지 못하면
`부분적으로 맞음` 이다.

## 2. 채점 기준 서식 (내부 메모 — 답장에 쓰지 않는다)

```
Q3 [유형 3 · 난이도 중] 클로저가 루프 변수를 잡는 방식
요점: ① var 는 함수 스코프라 콜백 셋이 같은 i 를 본다 (p.57)
      ② 콜백은 루프가 끝난 뒤 실행되어 i=3 을 읽는다
      ③ let 은 반복마다 새 바인딩을 만든다 (p.58)
흔한 오답: "setTimeout 이 0ms 라서 바로 실행된다"
판정: 맞음 = ①② + 이유 / 부분 = 출력만 맞음 / 틀림 = 그 밖
```

요점은 학습자가 자기 말로 말해도 인정한다. 용어를 정확히 쓰지 않았다는 이유만으로 깎지 않되, 용어를
잘못 쓰면(다른 개념의 이름을 쓰면) 짚는다.

## 3. 코드 문항 파일

- **위치:** 항상 `~/.claude/interview/YYYY-MM-DD/qNN-<slug>/`. 어느 repo 도 더럽히지 않는다. 첫 코드
  문항에서 경로를 알린다.
- **구성:** 학습자가 고칠 파일 하나 + 테스트 파일 하나 + 폴더 안 `README.md` 에 실행 명령 한 줄.
  설치가 필요 없는 실행 방법을 고른다(Node 는 `node --test`·`assert`, TypeScript 는 설치된 `tsc` 로 컴파일한 뒤 `node`,
  Python 은 `assert` 스크립트). 정답 코드는 학습자 폴더에 두지 않는다.
- **출제 전 확인:** 정답 코드를 학습자 폴더 밖의 임시 폴더(scratchpad, 없으면 `mktemp -d`)에 두고 테스트가 통과하는 것과, 빈칸·버그·스텁 상태에서 실패하는 것을 직접
  실행해 확인한다. 출력 예측 문항의 정답은 그 코드를 실행한 출력이다.
- **채점:** 학습자가 "다 했어요"라고 하면 테스트를 실행하고 출력을 그대로 보여 준 뒤 판정한다.
  학습자의 파일을 대신 고치지 않는다. 힌트 ③ 에서도 대화로만 보여 준다.
- **정리:** 마무리 때 그날 폴더를 지우고 지웠다고 알린다. 학습자가 남겨 달라고 했으면 남기고 경로를 알린다.
