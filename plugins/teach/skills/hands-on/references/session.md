# 세션 모드

`.teach/notes.md` 가 있을 때 들어온다. 지난 세션의 기억은 없다 — **노트·장부·git log 로 현재 상태를
복원**하고, 다음 할 일을 판정해 학습자에게 제안한다.

---

## 1. 상태 읽기

모두 읽고 나서 판정한다.

- `.teach/notes.md` — 설정, 이해도, 열린 질문, 오개념, 다음 세션 계획
- `authoring/01-커리큘럼.md` — 현재 장과 그 앞뒤 장
- `authoring/03-진행-장부.md` 의 `## 장별 상태`
- `git log --oneline -20`
- `git status --porcelain`

## 2. 판정 — 위에서부터 적용

처음 들어맞는 줄에서 멈춘다. "현재 장"은 notes 의 "현재 위치"가 가리키는 장이고, 그 장의 상태는
장부에서 읽는다.

| # | 상태 | 할 일 |
|---|---|---|
| 1 | `git status --porcelain -- code/` 에 커밋 안 된 변경이 있다 | **실습 진행 중.** 막힌 곳이나 질문이 있는지 확인하고, 다 됐으면 `[실습]` 커밋을 안내한다 |
| 2 | 마지막 `[과제]` 뒤에 `[실습]` 이 있고, 그 뒤에 `[피드백]` 이 없다 | **리뷰** (`references/practice.md`) |
| 3 | `[피드백]` 뒤인데 장부 답안이 `공개 대기` 다 | 학습자가 재제출을 원하지 않으면 **답안공개** (`references/practice.md`). 고쳐서 다시 내겠다면 기다린다(다음 호출에서 1·2 로 이어진다) |
| 4 | 현재 장의 답안이 `공개 완료` 다(실습 `없음` 인 장은 `즉시 동봉` 이면 끝난 것으로 본다) | **다음 장** — 교재 집필 또는 설명 → 과제 출제 |
| 5 | 장부와 git log 가 어긋난다(예: 장부는 `피드백 완료` 인데 `[피드백]` 커밋이 없다) | **멈추고 보고한다.** 임의로 고치지 않는다 |

어느 줄에도 들어맞지 않거나 두 줄이 서로 다른 답을 내면 5와 같이 멈추고 보고한다.

**제안.** 판정 결과에 notes 의 "다음 세션 계획"과 "오개념"을 얹어 **방향 1~3안**을 낸다. 하나에
"(권장)"을 붙이고 근거를 한 줄 적는다. 예:

> 1. 2장 과제 리뷰 (권장) — 어제 커밋하신 `[실습]` 이 아직 리뷰 전입니다.
> 2. 지난번 헷갈리셨던 클로저를 퀴즈 3문제로 다시 짚기
> 3. 3장 교재 먼저 읽기

`$ARGUMENTS` 가 있으면 그것이 우선한다. 다만 판정 1·2·5 에 걸리면 그 사실을 먼저 알리고 진행한다.

## 3. 활동

어느 활동이든 **학습자의 이해도를 계속 확인한다** — 설명 뒤 한 문장으로 되묻기, 리뷰 중 "왜 이렇게
하셨나요" 묻기. 방향은 세션 중간에 바꿔도 된다.

- **설명** — 대화로 개념을 풀어 준다. 교재에 이미 있으면 그 장·페이지를 가리키고 교재에 없는 각도로
  설명한다. 남길 가치가 있는 설명이면 다음 교재 집필에 반영할 것을 notes 에 적는다.
- **실습 출제** — `references/practice.md`. `[과제]` 커밋, 장부 실습 칸 `진행`.
- **리뷰** — `references/practice.md`. `[피드백]` 커밋, 장부 실습 칸 `피드백 완료`.
- **퀴즈** — 대화형으로 3~5문. 틀린 답은 왜 틀렸는지 짚고 오개념이면 notes 에 적는다. 교재에 남길
  가치가 있으면 Agent 도구로 `teach:textbook-writer` 를 수정 모드로 불러 교재에 넣는다. 이때는
  hands-on 이 오케스트레이터 몫을 한다 — `teach:textbook-reviewer`(새 인스턴스)로 검수하고, FIX 는
  지적 원문을 writer 에 돌려 최대 2회까지 고치고, PASS 뒤에만 `[퀴즈]` 로 커밋한다.
- **교재 집필** — Skill 도구로 `teach:textbook-html`, args `teach 연동: <N>장 집필, 답안 후공개`.
  textbook-html 이 집필·리뷰·`[교재]` 커밋과 장부 교재 칸까지 맡는다. 돌아오면 `git log -1` 로 커밋을
  확인한다.
- **답안공개** — `references/practice.md`.
- **노트 갱신** — 아래 5.

## 4. 장 한 바퀴 — 기본 순서

1. `[기획]` 이 장의 커리큘럼 확정(`(예정)` 이었다면 상세로), 코드가 누적되면 정본 시그니처 고정
2. (개념이 필요하면) `[교재]` 집필 — 과제 모범답안 자리는 자리표시자
3. `[과제]` 출제
4. `[실습]` ↔ `[피드백]` 반복
5. `solutions/chNN/` 작성
6. `[답안공개]`
7. 태그 `chNN-done` (상담에서 켰으면)
8. (필요할 때만) `[노트]`

과제와 교재의 순서는 바꿀 수 있다 — 먼저 부딪혀 보고 교재로 정리하는 편이 맞는 학습자도 있다.
바꿀 때는 학습자에게 이유를 말하고 권고안을 낸다.

## 5. 마무리

- notes 는 **의미 있는 상태 변화가 있을 때만** 갱신한다(이해도 단계가 바뀜, 새 오개념, 분담 비율 변경,
  다음 계획이 바뀜). git log 로 충분하면 생략한다. 갱신하면 `[노트]` 커밋.
- notes 에 장별 진행 상태를 중복해 적지 않는다 — 정본은 장부다.
- 끝으로 다음 세션 제안을 한 줄로 말한다.
