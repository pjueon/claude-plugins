# 외부 프로젝트 분석

학습 유형 b(기존 프로젝트 코드 읽기·분석)에서 쓴다. 분석 대상인 원본 프로젝트와 학습 repo 는
**별개의 폴더**다. 원본은 읽기만 하고, 기록·과제·교재는 모두 학습 repo 에 남긴다.

---

## 1. 기록 — URL 과 SHA 만

- notes 의 "외부 프로젝트" 줄에는 **URL, SHA, 분석 범위만** 적는다.
- **로컬 경로는 어떤 파일에도 적지 않는다.** PC 가 바뀌면 경로가 틀어지고, 학습 repo 가 공개되면
  사용자의 폴더 구조가 드러난다.
- 원격이 없는 로컬 프로젝트는 `원격 없음: <이름> @ <SHA>` 로 적는다. 이때는 **교재 발췌가 원본의
  유일한 사본**이 되므로 발췌를 넉넉히 한다(4).

## 2. 원본 읽기 — 작업 트리를 건드리지 않는다

1. 대화(세션)마다 한 번, 원본의 로컬 경로를 학습자에게 묻는다(기록하지 않으므로 새 대화마다 필요하다). 아직 받아 두지
   않았다면 **학습 repo 밖에** clone 하도록 제안한다.
2. `git -C <원본> rev-parse HEAD` 가 기록된 SHA 와 다르면 학습자에게 알린다.
3. 그래도 **checkout 하지 않는다.** 기록된 SHA 의 파일을 직접 읽는다.
   ```bash
   git -C <원본> show <SHA>:<파일 경로>
   git -C <원본> ls-tree -r --name-only <SHA> -- <폴더>
   ```
   학습자가 원본에서 다른 작업을 하고 있을 수 있다. 작업 트리를 바꾸면 그 작업을 망가뜨린다.

분석 기준 SHA 를 바꾸는 것은 커리큘럼 변경이다. 학습자에게 이유와 함께 권고하고, 동의를 받으면 notes 와
교재 발췌 기준을 함께 갱신한다.

## 3. 직접 확인 과제

읽기 위주 학습에도 손으로 확인하는 과제를 반드시 하나 넣는다(SKILL.md "코드 분담").

- **흐름 추적 기록** — 요청 하나가 진입점에서 저장소까지 거치는 함수를 순서대로 적고, 각 단계에서
  무엇이 바뀌는지 한 줄씩. 학습 repo 의 `code/chNN/` 에 둔다.
- **발췌 재현** — 원본의 핵심 부분을 작게 떼어 와 혼자 실행되는 코드로 다시 만들어 본다. 역시
  `code/chNN/` 에. 출제 형태(`TODO(학습자)`·테스트·끝났다 기준)는 `references/practice.md` 를 따른다.
- **원본에서 실험적으로 고쳐 보기** — 학습자의 로컬에서만 하고, 끝나면 되돌리게 안내한다
  (`git -C <원본> stash` 또는 `git -C <원본> checkout -- .` 등을 학습자가 직접). 튜터는 원본을 고치지 않는다.

## 4. 교재 발췌

교재에 원본 코드를 인용할 때는 **스냅샷**으로 넣는다. 원본이 바뀌거나 사라져도 책은 읽혀야 한다.

- `pre` 블록으로 넣고, 바로 위에 **파일 경로 · SHA · 행 범위**를 적는다.
  예: `src/routes/loan.ts @ 3f2a9c1 · 12–48행`
- 원격이 없는 프로젝트는 앞뒤 맥락까지 넉넉히 발췌한다.
- 교재 집필을 부르기 전에(`teach 연동: <N>장 집필`) 발췌 대상 파일·SHA·행 범위를
  커리큘럼의 그 장 항목에 적어 둔다. 로컬 경로는 적지 않는다.
- Skill 은 같은 대화 안에서 돌므로, textbook-html 오케스트레이터는 이 세션에서 받은 원본 경로를 집필
  지시서에 담아 넘길 수 있다(지시서는 파일로 남지 않는다). 집필 에이전트도 `git -C <원본> show <SHA>:<파일>`
  로만 읽게 한다.
