# 상담 모드

`.teach/notes.md` 가 없을 때 들어온다. 상담이 끝나면 학습 repo 의 골격·기획·커리큘럼·노트가 생기고,
다음 호출부터는 세션 모드로 이어진다.

상담의 목적은 **이 학습자에게 맞는 책 한 권의 설계**다. 학습자의 말을 받아 적는 데서 멈추지 않는다.
이해도는 직접 짚어 보고, 설계는 튜터가 먼저 제안하고, 결정할 것은 권고안과 근거로 내놓는다.

---

## 1. 묻기

이미 대화나 `$ARGUMENTS` 에 나온 정보는 다시 묻지 않는다. 나머지를 모아 **한 번에** 묻는다.

| 항목 | 기본값 / 메모 |
|---|---|
| 주제 | — |
| 현재 이해도 | 아는 것·모르는 것을 **낱말 단위로** |
| 목표 | 다 배운 뒤 무엇을 할 수 있고 싶은가 |
| 학습 유형 | a 개념 학습 + 미니 프로젝트 / b 기존 프로젝트 코드 읽기·분석 / c 프로젝트를 정해 스텝 바이 스텝. 섞어도 된다 |
| 학습 시간 | 주당 몇 시간 × 몇 주 |
| 코드 분담 | 학습자 몫 많이 / 반반 / 적게(=읽기 위주). 기본 반반 |
| 교재 사용 | 기본 사용 |
| 장 완료 태그 | 기본 사용(`chNN-done`) |
| 예제 코드 언어 | — |
| (유형 b) 원본 | 원본 URL 과 분석 기준 커밋 |

**묻는 방법.** AskUserQuestion 은 한 번에 담을 수 있는 질문·선택지 수가 적다.
그래서 둘로 나눈다.

1. 자유 서술 항목(주제·이해도·목표·시간·원본 URL)은 대화로 한 번에 묻는다.
2. 선택 항목(유형·분담·교재·태그·언어)은 AskUserQuestion 으로 묶는다. 1의 답을 보고 **권장 선택지를
   맨 앞에 "(권장)" 으로 두고**, 설명에 근거를 한 줄 적는다. 예: 이해도가 낮고 시간이 넉넉하면
   "반반 (권장) — 핵심 로직은 직접 쓰되 설정·테스트는 튜터가 맡아 막히는 시간을 줄입니다."

**이해도는 짚어 본다.** 학습자의 자기 평가만 믿지 않는다. 주제의 기초 개념으로 짧은 확인 질문을
한두 개 던지고(예: "이 코드에서 `await` 를 빼면 무엇이 달라질까요?"), 답을 보고 아는 것·모르는 것을
고쳐 적는다. 짚은 결과는 학습자에게 그대로 말해 준다("○○ 은 익숙하시고, △△ 부터 설명이 필요해
보입니다").

질문을 마치면 **방향은 중간에 바뀌어도 된다**고 알린다. 커리큘럼은 세션마다 고칠 수 있다.

## 2. 유형별 기본 설계

답을 바탕으로 설계를 **먼저 제안한다** — 유형 배합, 처음 두세 장, 코드 분담을 각각 근거와 함께.

| 유형 | 장 구성 | 기준 예제·실습 |
|---|---|---|
| a 개념 + 미니 프로젝트 | 개념 장과 미니 프로젝트 장을 번갈아 | 미니 프로젝트가 기준 예제 |
| b 기존 프로젝트 분석 | 장 = 원본의 한 영역. 구조 → 진입점 → 핵심 흐름 → 프레임워크 관용구 | `code/` 에 직접 확인 과제(`references/external-project.md`) |
| c 스텝 바이 스텝 | 장 = 기능 한 스텝. 예: 도서 대여 시스템이면 DB 스키마 → 조회 API → 대여 트랜잭션 → 화면 | 교재는 그 스텝에 필요한 개념만 |

흔한 요청과 기본 매핑:

- "TS/Node.js 기초를 배운 뒤 구체적인 프로젝트를 만들고 싶다" → a 로 시작해 후반을 c 로.
- "Vue.js 를 배우고 간단한 앱을 만들고 싶다" → a(미니 프로젝트 = 그 앱).
- "사내 도서관 책 대여 웹시스템을 만들며 배우고 싶다" → c.
- "Claude 로 만든 기존 프로젝트의 코드를 까 보고 싶다" → b(필요한 개념 장을 a 로 끼운다).

## 3. 커리큘럼

서식은 `../textbook-html/references/plan-and-curriculum.md`(스킬 기본 디렉터리 기준) 를 그대로 쓴다(기획서 §1,
커리큘럼 §2). 학습자와 상의해 두 방식 중 하나를 고른다.

- **확정 범위까지 상세 + 이후 `(예정)` 한 줄** — 권장. 학습자의 진도와 이해도를 보며 뒷장을 정할 수
  있다. 특히 유형 b·c 처럼 해 봐야 다음이 보이는 학습에 맞다.
- **전체를 잡고 나중에 수정** — 목표가 분명하고 범위가 정해진 주제(시험·자격 준비 등)에 맞다.

교재를 생략해도 `authoring/00-기획.md` 와 `authoring/01-커리큘럼.md` 는 만든다. 커리큘럼 정본은 이
파일 하나다.

## 4. 골격 만들기

1. 필요하면 `git init`.
2. `docs/` `authoring/` `code/` `solutions/` `.teach/` `README.md` 를 만든다. README 에는 이 책을
   읽는 방법(교재 여는 법, 과제 흐름, 커밋 접두어 표)을 적는다.
3. 언어에 맞는 `.gitignore`. **`.teach/` 는 ignore 하지 않는다**(노트도 커밋한다).
4. 교재를 쓰면 textbook-html 의 절차 3(골격 세우기)을 **전부** 한다 — assets·`_smoke.html`·`index.html`
   복사, `docs/.nojekyll`, `book.js` 의 `[교재별 1/5]`~`[교재별 5/5]` 블록(제목, `STORE_KEY` 는 이 repo
   고유 접두어로 — 기본값을 두면 `file://` 로 연 다른 교재와 진도가 섞인다), `index.html` 의 ▣ 채우기.
   원본은 이 스킬의 기본 디렉터리 기준 `../textbook-html/templates/` 다. `BOOK` 은 확정된 장과 `(예정)` 장으로 채운다.
   textbook-html 은 "지시된 장만 처리"하므로 이 골격 작업은 상담이 맡는다.
5. `authoring/03-진행-장부.md` 를 만들고 `## 장별 상태` 표를 넣는다(SKILL.md 의 계약 그대로).
   교재를 생략해도 장부는 만든다. 확정된 장마다 한 행을 넣는다 — 실습 `대기`, 답안 `공개 대기`,
   태그 `—`. 교재 칸은 집필 커밋 때 오케스트레이터가 채우고, 교재를 생략했으면 지금 `생략` 을 적는다.
   과제가 없는 장(개념만 다루는 장)은 실습 `없음`, 답안 `즉시 동봉`.
6. 코드가 장을 넘어 누적되면 `authoring/02-코드-정본.md` 를 만든다. **시그니처·자료형·파일 배치만**
   적고 구현 본문은 적지 않는다 — 학습자가 미리 볼 수 있는 파일이다.
7. `.teach/notes.md` 를 `templates/notes.md` 서식으로 채운다. 1에서 짚은 이해도와 근거를 적는다.

## 5. 커밋과 다음 단계

커밋은 둘이다.

1. `[기획] 학습 repo 골격과 커리큘럼(…)` — 괄호에 주제와 확정 범위를 짧게. `.teach/` 는 2번 커밋에 둔다.
   예: `[기획] 학습 repo 골격과 커리큘럼(Vue.js 기초, 1~3장 확정)`
2. `[노트] 상담 결과 기록`

마치면 상담 결과(유형, 확정된 장, 분담)를 세 줄로 요약하고 **곧바로 첫 세션으로 이어 갈지** 묻는다.
이어 가면 `references/session.md` 로 넘어간다.
