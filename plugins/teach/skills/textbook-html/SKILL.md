# textbook-html — 학습 교재(HTML) 집필 도구

**대상:** $ARGUMENTS  *(주제 + 독자 배경 + 쓸 수 있는 학습 시간)*

목표는 하나다 — **혼자 읽어도 이해되는, 친절한 학습 자료.** 주제 하나를 **여러 장짜리
교재 한 권**으로 만든다. 커리큘럼을 먼저 잡고, 이후 집필은 메인이 오케스트레이터가 되어
집필·리뷰 에이전트에 장 단위로 맡긴다. 산출물(`docs/`)과 집필용 문서(`authoring/`)는 폴더를 나눠 커밋하며, 장이 추가되며 자라는 자산이다.

주제는 코드에 한정되지 않는다 — **수학·알고리즘·공학·업무 지식**도 대상이다.
문서와 교재 본문은 한국어 존댓말로 쓴다(코드·수식·식별자 인용은 원문 그대로).

문서 골격·CSS·페이지 넘김·진도·퀴즈 채점은 **동봉 런타임이 이미 갖고 있다.** 부른 쪽이
쓸 것은 **내용과 페이지 구성**, 그리고 필요할 때의 **시각화**다.

## 산출물 구조

```
docs/                   독자에게 나가는 산출물만 둔다 (GitHub Pages 배포 폴더로 그대로 쓸 수 있다)
  index.html            표지 + 목차 + 학습 트랙
  ch00.html … chNN.html
  glossary.html         (선택) 용어집 부록
  assets/book.css       동봉본. 손대지 않는다
  assets/book.js        동봉본. [교재별] 다섯 블록만 고친다
  assets/math.js        동봉본. 수식(KaTeX) 렌더 호출. 손대지 않는다
  assets/katex/         동봉본. KaTeX 로컬 사본(CSS·JS·woff2 글꼴). 손대지 않는다
  .nojekyll             빈 파일. GitHub Pages 가 Jekyll 처리를 건너뛰게 한다

authoring/              집필에 필요한 저자용 문서. 독자에게 나가지 않는다
  00-기획.md            독자·학습목표·기준 예제·형식 결정 (집필 전)
  01-커리큘럼.md        장별 항목 · 페이지 수 · 시간 (집필 전)
  02-코드-정본.md       (코드가 장을 넘어 누적되거나 `code/`·`solutions/` 를 동봉하는 교재는 필수) 시그니처 고정
  03-진행-장부.md       장 사이 약속·용어 정의 기록 (집필 에이전트 간 인계)
  _smoke.html           런타임 점검 54 단정 (../docs/assets 를 참조)

code/                   (실습 코드를 동봉하는 교재) 학습자가 작성하는 코드. 장을 거치며 누적된다
solutions/chNN/         (같은 경우) 그 장 완료 시점의 모범 상태 스냅샷
.teach/                 (hands-on 연동 시) AI 용 현재 상태 요약 notes.md. hands-on 소유, 이 스킬은 읽기만 한다
```

`docs/` 에는 독자가 읽을 파일만 둔다. 기획서·커리큘럼·점검 페이지가 섞여 있으면
배포할 때 저자 전용 문서가 함께 노출된다.

## 규약 R1~R8

### 기술 제약 — 어기면 산출물이 깨진다

- **R1** **장 = HTML 파일 1개, 장 안은 페이지(`section.screen`) 단위**, 페이지당 10~12분.
  마크업은 `templates/ch-template.html` 에 있는 것만 쓴다(위젯은 예외 — R6).
  새 CSS 클래스나 외부 라이브러리를 만들지 않는다.
- **R2** **`file://` 로 더블클릭해서 열린다**(웹서버 없음). `fetch()` 로 로컬 파일을 읽지
  않고, `<script type="module">` 을 쓰지 않고, **CDN·외부 폰트를 쓰지 않는다.** 본문은 각 장
  HTML 에 인라인으로 넣는다. 수식 라이브러리는 동봉된 로컬 KaTeX 만 쓴다(아래 "수식" 절). 진도는 `localStorage` + try/catch, 키에 교재별 접두어를 붙인다.

### 서술 원칙 — 교재를 교재답게 만드는 것

- **R3** **기준 예제 하나**를 교재 전체에서 이어 쓴다. 장마다 소재가 바뀌면 앞장에서 쌓은 것이
  뒷장에서 버려지고, 독자는 매번 새 맥락을 이해하는 데 힘을 쓴다.
- **자기완결.** 교재 본문과 `authoring/` 문서(기획·커리큘럼·장부·README 포함)에서 이 플러그인이나 스킬, 에이전트 이름을 직접 언급하지 않는다. 산출물은 플러그인 없이도 읽히고 이어 작업할 수 있어야 하므로, 규약·절차는 "~한다"처럼 그 문서 안에서 설명하고 `textbook-html`·`R1~R8`·`SKILL.md` 같은 이름으로 가리키지 않는다.
- **R4** **개념 → 이름 순서.** 문제 상황을 먼저 보이고 이름은 나중에 붙인다.
  **이름이 붙은 페이지보다 뜻을 설명하는 페이지가 앞**에 온다.
- **R5** **던져놓고 넘어가지 않는다.** 이 교재의 존재 이유다.
  - 20줄 넘는 코드에는 `ol.notes` 행별 해설 — "몇 행 + 무엇을 + **왜 그렇게**".
  - 처음 나오는 수식·기호·용어는 **그 자리에서** 뜻을 밝힌다. 수식은 기호마다 무엇인지 적는다.
  - 전체 구조를 세부보다 먼저 보여준다(스키마·블록도·데이터 흐름).
  - 독자가 모른다고 가정한 것을 기획서 §1 에 적고 그것을 지킨다.
  - **한계와 반례를 숨기지 않는다** — 언제 이 방법이 안 통하는지, 가정이 깨지면 어떻게 되는지.
- **R6** **필요하면 그림·그래프·인터랙티브 위젯을 만든다.** 아래 "시각화" 절과 `../../shared/visuals.md` 참조.
  억지로 만들지 않는다 — 글로 충분한 곳에 위젯을 얹으면 읽기가 느려진다.
- **R7** **매 장의 마지막 페이지 = 핵심 요약(3~5줄) + 퀴즈 + 직접 해보기.** 퀴즈의 모든
  선택지에 `data-why`(왜 맞고 왜 틀리는지)를 달고, 해설에는 본문에 없는 이야기를 하나
  얹는다. 과제에는 **모범답안을 접어서(`details.fold answer`) 넣는다** — 혼자 공부하는
  독자에게는 리뷰해 줄 사람이 없다. 동봉 방식은 두 가지다.
  - **즉시 동봉**(기본, 독립 교재): 집필할 때 모범답안을 함께 넣는다.
  - **후공개**(학습자가 `code/` 에서 과제를 수행하는 교재): `fold-body` 에는 자리표시자
    (`<!-- teach:answer-pending -->` 와 `references/authoring.md` "자주 틀리는 것" 9번의 정해진 문구)만 넣고 바로 커밋한다. 실제 답안은
    별도 "답안공개" 루프가 넣는다(`references/orchestration.md`).

  공개 시점까지 답이 반드시 들어간다 — 답 없는 과제는 내지 않는다.

### 진행 게이트

- **R8** **장 단위로 집필→리뷰→커밋**하고, 기본은 순차다(뒷장이 앞장·약속과 어긋나지 않게).
  의존이 없고 약속이 고정된 장만 병렬로 묶을 수 있다. **리뷰 PASS 없이 완료로 보고·커밋하지 않는다.**
  장 커밋 메시지는 `[교재]` 접두어로 시작한다(예: `[교재] 3장 집필: 정규화와 키 설계 (12페이지)`).
  독립 교재에도 같다. 커리큘럼이 부분만 확정돼 있어도 확정된 장까지 집필할 수 있다.

## 절차

### 1) 기획 확정 — `authoring/00-기획.md`

`authoring/00-기획.md`·`01-커리큘럼.md` 가 이미 있으면(hands-on 상담이 만든 경우 포함)
아래 네 질문을 다시 하지 않고 읽어서 이어 간다.

주제만 던졌으면 **네 가지를 먼저 묻는다**(나머지는 알아서 정하고 결정으로 적는다).

1. **독자가 이미 아는 것과 모르는 것** — 교재의 난이도가 여기서 정해진다.
2. **쓸 수 있는 총 학습 시간** — 주당 몇 시간 × 몇 주. 장 수가 여기서 나온다.
3. **기준 예제로 쓸 소재** — 없으면 후보 2~3개를 제안하고 고르게 한다.
4. **예제 코드의 언어**(코드가 나오는 주제라면) — 하이라이터 키워드가 이걸로 정해진다.

서식과 완료 기준은 `references/plan-and-curriculum.md` §1.

### 2) 커리큘럼 — `authoring/01-커리큘럼.md`

장별 **항목 · 페이지 수 · 시간**을 정한다. 이 세 값이 집필의 계약이다.
배분 기준은 같은 참조 문서 §2. 두 방식 모두 허용한다.

- 확정 가능한 장까지만 상세히 쓰고 나머지는 `(예정)` 한 줄로 둔다.
- 전체를 잡고 나중에 수정한다.

확정되면 `book.js` 의 `BOOK` 배열에 옮겨 적는다. 예정 장은 `ready` 없이 넣는다(목차에
'집필 예정'으로 표시되며 런타임 수정은 필요 없다). 표지 학습 트랙은 확정 범위의 합계로 적고,
장이 늘 때 갱신한다. **사람의 확인을 받고 다음으로 간다.** hands-on 이 부른 경우에는
상담·세션에서 받은 확인으로 갈음한다.

### 3) 골격 세우기 (첫 장 전에 한 번)

```bash
mkdir -p docs authoring
cp -r <skill>/templates/assets       docs/assets
touch docs/.nojekyll
cp    <skill>/templates/_smoke.html  authoring/_smoke.html
cp    <skill>/templates/index.html   docs/index.html       # ▣ 주석 자리를 채운다
cp    <skill>/templates/ch-template.html docs/ch00.html    # 장마다 복사해서 쓴다
```

`authoring/03-진행-장부.md` 도 이때 만든다(서식은 `references/orchestration.md`).

`book.js` 에서 고칠 곳은 `[교재별 1/5]`~`[교재별 5/5]` 다섯 블록뿐이다 —
`TITLE`/`SUBTITLE`(사이드바 머리), `BOOK`(목차), `TERMS`(툴팁 용어집),
`STORE_KEY`(진도 키 접두어), `PY_KW`(하이라이터 키워드).
`TERMS` 의 `_smoke` 항목은 점검이 참조하므로 지우지 않는다.

### 4) 장 집필 — 오케스트레이션

**메인은 오케스트레이터만 한다.** 장 본문은 `teach:textbook-writer` 가 쓰고,
`teach:textbook-reviewer` 가 검수하고, 메인이 장마다 커밋한다.
루프·진행 장부·병렬화 조건·지시서 내용은 `references/orchestration.md`.
집필자가 따르는 집필 순서와 점검 명령은 `references/authoring.md`.

## 실습 코드 동봉

학습자가 `code/` 에서 과제를 수행하는 교재의 규약이다.

- `code/` 는 학습자가 작성한다. `solutions/chNN/` 은 그 장 완료 시점의 모범 상태 전체
  스냅샷이다(`node_modules` 등 산출물 제외). 규모가 크면 바뀐 파일만 두고 README 에 밝힌다.
- 본문 코드와 `solutions/` 는 `authoring/02-코드-정본.md` 를 따른다. 어긋나면 정본이 옳다.
- 정본 명세에는 **시그니처·자료형·파일 배치만** 적고 구현 본문은 적지 않는다. 학습자가
  미리 볼 수 있는 파일이기 때문이다.

## 수식

수식은 유니코드(`x⁽¹⁾`, `‖a‖`)를 `<code>` 에 넣지 말고 **LaTeX 로 쓴다.** 고정폭 글꼴로 나와
첨자가 어긋나고 분수·제곱근·Σ 한계 표기가 안 되기 때문이다.

- 문장 속은 `\( … \)`, 별행은 `<p style="text-align:center">\[ … \]</p>`.
- 코드 식별자·함수명(`SVC`, `np.dot`)은 수식이 아니라 `<code>` 로 둔다. `<pre>` 안은 렌더하지 않는다.
- HTML 안이므로 부등호는 `&lt;` 로 쓴다(`>` 는 그대로 가능).
- 노름은 `\lVert a\rVert`, 한글은 `\text{모든}` 으로 감싼다.
- 연산 기호는 **의미마다 다른 기호를 쓰고, 처음 쓰는 페이지에서 먼저 설명한다.** 같은 기호를 두 가지 뜻으로 쓰지 않는다.
  - 대상: 내적, 스칼라 곱, 숫자 곱, 원소별 곱, 외적, 합성곱 등 교재에 나오는 연산. 필요한 것만 다룬다.
  - 어떤 기호를 쓸지는 교재의 분야와 독자 관례에 맞춘다. 내적만 해도 `w\cdot x`, `w^{T}x`, `\langle x, y\rangle`, `\langle a|b\rangle` 처럼 다양하다. 하나를 골라 교재 전체에서 통일하고, 다른 책의 표기가 있으면 "다른 책의 표기" 상자로 짚는다.
  - 예시(내적을 `\cdot` 로 정한 경우): 스칼라 곱은 기호 생략(`tw`), 숫자 곱은 `\times`(생략하면 34 로 읽힌다), 원소별 곱은 `\odot`, 합성곱은 `*`.
  - 본문 텍스트·표의 `3·4` 도 같은 규칙을 따른다. 집필 후 `grep` 으로 같은 기호가 두 뜻으로 쓰인 곳이 없는지 훑는다.
- 렌더는 `math.js` 가 `<main id="book">` 안에서 한 번 한다. 스크립트는 반드시 `book.js` 앞에 둔다.
- 수식이 없는 교재는 `ch-template.html` 의 katex·math 줄을 빼도 된다.
- 위젯이 JS 로 만들어 내는 수식은 렌더되지 않는다(위젯 값은 숫자 위주로 쓰거나 `<code>`).
