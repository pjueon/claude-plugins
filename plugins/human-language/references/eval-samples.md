# 검수 회귀 확인용 샘플 (Eval Samples)

규칙이나 스킬을 고친 뒤 `review-writing-style`에 아래 입력을 넣어 기대 결과와 비교합니다. 런타임 스킬 실행용이 아닌 수동 점검용 문서입니다.

| # | 장르 | 입력 | 기대 결과 |
| :-- | :-- | :-- | :-- |
| 1 | 기술 문서 | `### 2. 가중치를 계산하는 방법을 알아본다` | BLOCK: 서술형 소제목. 대안은 명사구 |
| 2 | 블로그 | `## 왜 굳이 다시 써야 할까?` | 지적 없음 또는 NOTE (질문형 제목은 이 장르에서 허용) |
| 3 | 기술 문서 | `이 기능을 통해 성능 개선이 이루어질 수 있을 것으로 생각되어집니다.` | BLOCK: 조사 직역과 이중 피동. 대안 예: "이 기능으로 성능을 개선할 수 있습니다." |
| 4 | 기술 문서 | `요청은 서버를 통해 전달됩니다.` | 지적 없음 또는 NOTE (자연스러운 `~를 통해`) |
| 5 | 기술 문서 | `이 값은 0이 될 수 있습니다.` (실제로 0이 될 가능성을 뜻함) | 지적 없음 (가능성 의미 유지) |
| 6 | 기술 문서 | `지원하는 형식은 JSON, YAML, TOML입니다.` | 지적 없음 (내용상 3개) |
| 7 | 영어 | `We need a comprehensive test plan.` | 지적 없음 (과대표집 어휘 하나, 구체적) |
| 8 | 영어 | `This vibrant, holistic, seamless platform is a testament to innovation.` | 과대표집 어휘 다수. 구체적 사실로 대체 제안 |
| 9 | 소설 | `그의 마음속에서 바다가 울었다.` | 지적 없음 (문학적 비유 허용) |
| 10 | 사용자 요청 | "질문형 제목 허용"이라는 요청과 함께 질문형 소제목 | 지적 없음 (사용자 요청 우선) |
