# record-language-feedback 스킬

사용자의 실제 지적과 피드백을 오답 노트에 누적하여, AI가 점진적으로 사용자의 개인 취향과 프로젝트 기준에 정렬(Alignment)되도록 만듭니다.

---

## 1. 피드백 유형별 처리 규칙

### 유형 A: 영구 지침형 피드백 ("앞으로 A 대신 B 써", "C 표현 금지")
* **동작**: **사용자에게 되묻지 않고 즉시 오답 노트에 기록**합니다.
* **스코프 결정**:
  - 프롬프트에 특정 프로젝트나 파일 언급이 있으면 ➔ 프로젝트 스코프에 기록.
  - 범용적인 문체 선호이고 프로젝트 특정성이 없으면 ➔ 전역 스코프(`~/.claude/writing-feedback.md`)에 기록.
  - 적용 범위가 완전히 모호할 때만 한 줄로 질문: *"이 규칙을 이 프로젝트에만 적용할까요, 아니면 모든 프로젝트(전역)에 적용할까요?"*

### 유형 B: 문맥 교정형 피드백 ("여기 X 표현 어색하니 Y로 바꿔")
* **동작**:
  1. 본문의 텍스트를 Y로 즉시 교정합니다.
  2. 현재 활성화된 오답 노트 파일들을 확인하여, **이미 유사한 규칙(X ➔ Y)이 기록되어 있는지 확인**합니다.
  3. **이미 유사 규칙이 있는 경우**: 질문 없이 §3의 절차(근거 추가, 병합·일반화)로 기록하고 작업을 마칩니다.
  4. **완전히 새로운 패턴인 경우**: 가볍게 제안합니다:
     *"교정 완료했습니다. 앞으로도 'X' 대신 'Y'를 사용하도록 오답 노트에 기록해 둘까요?"*

---

## 2. 오답 노트 저장 위치 및 포맷

### 저장 위치
1. **전역 스코프**: `~/.claude/writing-feedback.md`
   - 파일이 없으면 템플릿 형태로 자동 생성합니다.
2. **프로젝트 스코프**: `./.claude/writing-feedback.md` (없으면 템플릿으로 생성). CLAUDE.md는 늘리지 않습니다.
   - 프로젝트의 CLAUDE.md에 이미 `### 사용자 교정 이력` 섹션이 있는 경우에만 그 섹션에 기록합니다.

### 노트 구조

시간순 로그가 아니라 분류별 규칙 목록으로 관리합니다. 규칙마다 원칙 한 줄을 두고, 근거가 된 사용자 지적을 아래에 보존합니다.

```markdown
## 교정 내역 (오답 노트)

### <분류>
- **<규칙 한 줄>** (적용 문맥: <상황/장르 또는 공통>)
  - 근거: [지적 YYYY-MM-DD] "<지양할 표현>" ➔ "<권장 표현>" (이유/메모)
```

분류는 `번역투·문형`, `어휘 치환`, `구조·제목`, `장르별 어투`, `기타`를 기본으로 하되 기존 노트의 분류가 있으면 따릅니다.

**예시**:
```markdown
### 어휘 치환
- **이메일 요청 표현은 외래어·구어체 대신 공문체를 쓴다** (적용 문맥: 업무 이메일)
  - 근거: [지적 2026-10-08] "컨펌 부탁드립니다" ➔ "확인해 주시기 바랍니다"
  - 근거: [지적 2026-10-09] "픽스 부탁드려요" ➔ "수정해 주시기 바랍니다"

### 구조·제목
- **문단 첫머리에 맥락 없는 단정문을 쓰지 않는다** (적용 문맥: 공통)
  - 근거: [지적 2026-10-09] "힘의 균형입니다." 같은 단정문 금지
```

## 3. 기록 절차: 비교, 병합, 일반화

새 지적을 기록하기 전에 대상 파일을 Read/Grep하여 기존 규칙과 비교하고, 결과에 따라 하나만 수행합니다.

| 비교 결과 | 처리 |
| :--- | :--- |
| 같은 규칙이 이미 있음 | 새 줄을 만들지 않습니다. 새로운 사례일 때만 기존 규칙의 근거에 추가합니다. |
| 같은 취지의 규칙이 이미 1건 있음 | 두 건의 공통 원칙을 상위 규칙으로 만들어 묶고, 두 건의 근거를 모두 보존합니다. |
| 기존 규칙과 충돌함 | 최신 지적을 우선해 그 규칙을 제자리에서 고쳐 씁니다. 사용자가 방금 직접 한 지적이므로 확인을 구하지 않습니다. |
| 관련 규칙이 없음 | 해당 분류에 구체 규칙으로 새로 추가합니다. |

* **일반화는 근거 2건부터**: 지적이 한 번뿐인 표현은 일반화하지 않고 그 표현 그대로 기록합니다. 한 건을 근거로 단어를 전역 금지어로 넓히지 않습니다. (`../../shared/reviewer-guide.md` §4)
* **근거 보존**: 병합·일반화해도 개별 지적(근거)은 지우지 않습니다. 일반화가 틀렸을 때 되돌릴 수 있어야 합니다.
* **알림**: 병합이나 일반화를 했다면 기록 직후 한 줄로 알립니다. (예: "기존 '컨펌' 규칙과 묶어 '이메일 요청 표현은 공문체' 규칙으로 일반화했습니다.") 질문은 하지 않습니다. 사용자가 되돌리라고 하면 근거를 바탕으로 원래 항목으로 복원합니다.

---

## 4. 오답 노트 정리

* 파일이 200줄을 넘으면 기록 전에 구조 정리를 제안합니다. 사용자가 동의하면 분류를 재편하고, 같은 취지의 규칙을 병합·일반화합니다. 이때도 근거는 보존합니다.
* 지적일 기준 1년이 지난 규칙은 삭제 후보로 제시하고, 사용자가 확인한 것만 삭제합니다. 사용자 확인 없이 규칙이나 근거를 삭제하지 않습니다.
