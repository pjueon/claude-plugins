# record-language-feedback 스킬

사용자의 실제 지적과 피드백을 오답 노트에 누적하여, AI가 점진적으로 사용자의 개인 취향과 프로젝트 기준에 정렬(Alignment)되도록 만듭니다.

---

## 1. 피드백 유형별 처리 규칙

### 유형 A: 영구 지침형 피드백 ("앞으로 A 대신 B 써", "C 표현 금지")
* **동작**: **사용자에게 되묻지 않고 즉시 오답 노트에 기록**합니다.
* **스코프 결정**:
  - 프롬프트에 특정 프로젝트나 파일 언급이 있으면 ➔ 프로젝트 스코프에 기록.
  - 범용적인 문체 선호이고 프로젝트 특정성이 없으면 ➔ 전역 스코프(`~/.claude/writing-feedback.md`)에 기록.
  - 적용 범위가 완전히 모호할 때만 한 줄로 질문: *"이 규칙을 이 프로젝트에만 적용할까요, 아니면 모든 프로젝트(전역)에 적용할까요?"*

### 유형 B: 문맥 교정형 피드백 ("여기 X 표현 어색하니 Y로 바꿔")
* **동작**:
  1. 본문의 텍스트를 Y로 즉시 교정합니다.
  2. 현재 활성화된 오답 노트 파일들을 확인하여, **이미 유사한 규칙(X ➔ Y)이 기록되어 있는지 확인**합니다.
  3. **이미 유사 규칙이 있는 경우**: 질문 없이 조용히 작업을 마칩니다.
  4. **완전히 새로운 패턴인 경우**: 가볍게 제안합니다:
     *"교정 완료했습니다. 앞으로도 'X' 대신 'Y'를 사용하도록 오답 노트에 기록해 둘까요?"*

---

## 2. 오답 노트 저장 위치 및 포맷

### 저장 위치
1. **전역 스코프**: `~/.claude/writing-feedback.md`
   - 파일이 없으면 템플릿 형태로 자동 생성합니다.
2. **프로젝트 스코프**: 프로젝트의 `CLAUDE.md` 내 `### 사용자 교정 이력` 섹션 (또는 `./.claude/writing-feedback.md`)

### 기록 형식 (Markdown)
```markdown
## 교정 내역 (오답 노트)
- [지적 YYYY-MM-DD] 문맥: "<상황/분류>" | "<지양할 표현>" ➔ "<권장 표현>" (이유/메모)
```

**예시**:
```markdown
- [지적 2026-10-09] 분류 문맥: "직선으로 가르다" ➔ "분류하다 / 나누다"
- [지적 2026-10-10] 이메일 문맥: "컨펌 부탁드립니다" ➔ "확인해 주시기 바랍니다"
- [지적 2026-10-11] 공통: 문단 첫머리에 "힘의 균형입니다." 같은 맥락 없는 단정문 금지
```

---

## 3. 중복 검사 가드레일 (Noise Reduction)

새로운 항목을 추가하기 전에 반드시 대상 파일을 Grep/Read하여:
* 동일하거나 거의 같은 취지의 규칙이 이미 등록되어 있다면 추가하지 않고 스킵합니다.
* 충돌하는 규칙이 있다면 최신 사용자 지적을 우선하여 갱신합니다.
